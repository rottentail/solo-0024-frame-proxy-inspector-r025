# Frame Proxy 实验讲解包

这是归档审片实验的独立交互式包。打开 `lab/viewer/index.html` 即可使用，不需要启动服务、不需要外网、没有第三方依赖。

包里的每个数字、每条边界、每张联系表和每个哈希都由**未修改的生产服务**真实产生。实验只通过 HTTP 调用服务，并在实验目录里逐帧读取已存 AVI 做验证。

## 直接打开

浏览器打开 `lab/viewer/index.html`（双击即可，`file://` 也能用，因为数据与帧文件都随包提供）。

七个步骤：

1. **逐帧切换原画面** — 滑块或方向键逐帧查看 200 帧源画面，每帧显示与源 RGB 逐字节对应的 SHA-256。
2. **观察实际场景分段** — 切换采样设置，查看服务接受的分界、设计真实镜头，以及被漏掉或合并的边界。
3. **联系表 ↔ 原帧对应** — 联系表每格都能回到它实际引用的原帧，并有“回到联系表”的返回链接。
4. **计算速度与判断质量的取舍** — 同一批素材、同样阈值下比较步长 1–4 的耗时与边界质量。
5. **反例** — 180° 旋转帧：统计特征完全无法分辨，人眼一眼可辨，服务判定为单一场景。
6. **中断与复用** — 客户端中途断开后服务自行提交终态记录；同 ID 重试被拒；实验复用已提交记录并逐帧验证。
7. **审计** — 交叉校验、实验条件与全部 HTTP 请求日志。

## 重新生成（会覆盖现有证据）

```bash
PYTHONPATH=src:. python3 -m lab.build_evidence
PYTHONPATH=src:. python3 -m lab.selfcheck
python3 -m compileall -q src tools lab
```

`build_evidence` 会启动真实的生产 HTTP 服务（随机回环端口 + 一次性数据根），通过公开 API 上传两段实验素材，跑完各采样设置的 inspection / contact sheet 流程，再生成证据与页面数据。生产源码未被修改。

页面也可以直接用静态服务器打开：

```bash
python3 -m http.server 8899 --directory lab/viewer
```

## 约束是怎么落实的

- **单任务驻留 ≤ 2 张源 RGB**：实验自己的每次扫描只保留一帧，`InFlightGuard` 在出现第二帧时直接报错。
  生产请求本身也由 `residency.py` 在运行时计数并逐次记录（`production_residency`），不是靠假设计算。
- **不预载完整帧序列**：素材生成器把每帧直接写进 AVI，实验不持有帧列表；查看器 PNG 在扫描结束后逐帧解码生成。
- **中断不拼接**：第一次请求在客户端中途断开，服务端继续跑到终态并提交；重试同 ID 返回 `409 conflict`；
  实验复用那条记录，并用已存 AVI 重新解码逐帧校验，再合成联系表。
- **不做手工修正**：反例（旋转帧）保留原结论 `cut_frames = []`；低对比硬切与两帧短镜头的漏检也原样展示。

## 已知事实（都写进证据里）

- 灵敏度 0.55 时阈值为 0.335。低对比硬切（帧 102、142）的距离只有 0.137/0.164，所有采样步长都漏检。
- 两帧短镜头在步长 4 下被完全跳过。
- 最小场景守卫（2 帧）会把对称的双边界（帧 110/112）合并为一条可接受边界。
- 耗时按每个设置 3 次独立请求的中位数记录，三次原始值同时公布；联系表始终由第 1 次记录合成。
